# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

WireGuard for Windows: a Go GUI client + Windows services on top of the WireGuardNT kernel driver. Module path `golang.zx2c4.com/wireguard/windows`. Further docs live in `docs/` (`buildrun.md`, `attacksurface.md`, `adminregistry.md`, `enterprise.md`, `netquirk.md`).

## Build

The build scripts download, hash-verify and extract a pinned toolchain into `.deps/` (Go, llvm-mingw, ImageMagick, make, wireguard-tools, wireguard-nt). Always build through them rather than a system Go: the build uses `-overlay .overlay/overlay.json`, which patches files under `.deps/go/src/crypto/...` (stubs out FIPS140/boringcrypto pieces), so it only works with the Go in `.deps/go`.

- Windows: `build.bat` → produces `x86\`, `amd64\`, `arm64\` each with `wireguard.exe` and `wg.exe`. Set `GoGenerate=yes` first to also run `go generate`.
- Linux (needs mingw-w64, imagemagick, bsdtar): `make` (all arches), `make amd64/wireguard.exe`, `make fmt`, `make generate`, `make deploy` (scp to `$DEPLOYMENT_HOST`, default `winvm`).
- Build flags used everywhere: `-tags load_wgnt_from_rsrc -ldflags="-H windowsgui -s -w" -trimpath -buildvcs=false`. `resources_<arch>.syso` (from `resources.rc` via windres) embeds the manifest, icons and the wireguard.dll from WireGuardNT; the `load_wgnt_from_rsrc` tag makes the driver package load it from those resources.
- Version comes from `version/version.go` (`Number = "..."`); the scripts parse it with regex, so keep that line format.
- Installer: `installer\build.bat` (WiX MSI). `quickinstall.bat` builds a local installer for testing self-built binaries. Optional signing via a `sign.bat` in repo root.
- Updating Go/deps: `make remaster` rewrites `go.mod` from `go.mod.master` and bumps the Go hashes in `Makefile` and `build.bat` — Go version/hashes must stay in sync across both files.

## Tests

Tests are ordinary Go tests but target Windows (`GOOS=windows`); many touch real Windows APIs (DPAPI, IP helper, WinHTTP) and some need admin. Using the `.deps` Go:

```
go test ./conf/...
go test ./tunnel/winipcfg -run TestName -v
```

Test packages: `conf`, `conf/dpapi`, `ringlogger`, `tunnel/firewall`, `tunnel/winipcfg`, `updater`, `updater/winhttp`, `version`.

## Generated code

- `zgotext.go` is generated by `gotext.go` (`//go:generate go run gotext.go`) from `locales/*/messages.gotext.json`; don't hand-edit. User-visible strings must go through `l18n.Sprintf` so they are extracted. Translations come from CrowdIn (`make crowdin`), not direct edits to non-`en` locales.
- `z*_windows.go` in `tunnel/firewall`, `tunnel/winipcfg`, `updater/winhttp` are produced by `mkwinsyscall` from the adjacent `syscall_windows.go` / `winipcfg.go`; edit the `//sys` declarations and regenerate.

## Architecture

One binary, `wireguard.exe`, whose role is selected by the command-line switch in `main.go` (`/managerservice`, `/tunnelservice CONFIG`, `/ui ...handles`, `/installmanagerservice`, `/dumplog`, `/update`, `/removedriver`, ...). With no argument it elevates and installs/starts the manager service.

- **Manager service** (`manager/`, LocalSystem): installs/tracks tunnel services (Windows services named `WireGuardTunnel$<name>`), enumerates user sessions and spawns the UI process with an elevated admin token (or a limited-operator UI when `LimitedOperatorUI` registry policy is set), hands it inherited unnamed pipes for gob-based IPC (`ipc_server.go`/`ipc_client.go`) plus a handle to the shared ringlog mapping. Also runs the updater.
- **Tunnel service** (`tunnel/`, one per tunnel, LocalSystem): creates/configures the WireGuardNT adapter via `driver/`, sets addresses/routes/DNS through `tunnel/winipcfg` (IP Helper API wrappers), applies kill-switch rules through `tunnel/firewall` (WFP), watches interfaces/MTU, runs Pre/Post Up/Down scripts, then drops privileges.
- **UI** (`ui/`): `lxn/walk` GUI (replaced by a WireGuard-maintained fork in `go.mod`), talks only to the manager over IPC; never touches drivers or config storage directly. `ui/syntax` is the config editor highlighter. The main window and the tray popup are custom-drawn: `scene.go` (anti-aliased shapes, GDI text, hit regions), `canvasview.go` (the widget), `screens.go`/`traypopup.go` (what is drawn), `model.go` (tunnel state and actions shared by both); `go test ./ui` with `WG_UI_RENDER_DIR=<dir>` writes PNG previews of every screen.
- **Config** (`conf/`): wg-quick style INI parser/writer, and the config store — DPAPI-encrypted `*.conf.dpapi` files in `C:\Program Files\WireGuard\Data\Configurations` with restrictive ACLs; admin registry policy readers in `admin_windows.go`.
- **Supporting packages**: `driver/` (WireGuardNT DLL bindings), `ringlogger/` (shared-memory log used by all processes), `elevate/` (token/UAC helpers), `services/` (service errors, boot-time helpers), `updater/` (signify-signed list + BLAKE2b-verified MSI download over `updater/winhttp`), `l18n/`, `version/`.
- `embeddable-dll-service/`: separate build of the tunnel service as a DLL (with C# example) for embedding in third-party apps.

Security matters here: services run as LocalSystem and the IPC/ACL/SDDL choices are deliberate — read `docs/attacksurface.md` before changing privilege dropping, pipe/file security descriptors, or the updater verification path.
